Session 0: You have eDNA data. Where do you start?

We will cover it in this session

Raw data following sequencing and bioinformatic analysis are not yet ready to be used to learn about the environment. Here, we will go through the checks and steps you should do to have a working dataset that you can trust.

We will achieve this by:

  1. Preparing our working environment.
  2. Consider assumptions, reshape data, and join taxonomy.
  3. Check laboratory controls for potential sources of contamination.
  4. Apply filters to remove contamination, and other weak-signal data.
  5. Join environmental metadata.
  6. Prepare community matrices alongside the associated metadata.
  7. Explore sequencing depth with rarefaction curves
  8. Explore sampling effort with species accumulation curves.
  9. Export outputs.

Here, we will use the example of an 18S dataset targeting metazoan invertebrates in a Scottish landscape and across four habitat types, heath, regen, commercial woodland, and mature woodland.

Analysis settings

We declare a few values in advance, as it makes it easier to explore how different filtering decisions affect the results. These include the confidence thresholds for taxonomic assignments and other relevant values.

The values below reproduce the thresholds in the original workflow. They are choices for this dataset rather than universal defaults.

A 70% confidence cutoff is the recommendation by the designers of the taxonomic classifier, called RDP naïve Bayesian classifier. A 0.1% filter is also typically used in eDNA studies to dismiss nuisance detections and focus on ecologically relevant data. A few samples were further removed if they did not have at least 3,000 reads, supported by rarefaction analysis.

Load data tables

Now we load our data. This will be a combination of data you hold, such as environmental metadata, and read and taxonomy data that is sent to you.

Read and taxonomy data will typically be in a “text” format, and split in several ways. Here, we have an ASV_table, which has Amplicon Sequence Variant (ASV) IDs as rows (i.e., each unique DNA molecule), and sample IDs as columns. The values within the cells correspond to the number of reads for a given ASV in a given sample. See example below.

Then, we have the ASV_tax. This table has the same ASV IDs alongside their taxonomic assignment and the confidence of that assignment.

We also have a conversion table from lab ID to field ID for our samples. This is because often, laboratories will use their own internal identifiers of samples, which are not the same as yours.

Lastly, the metadata. The four are connected through identifiers, and can be merged as follows:

  • asv_id connects read counts to taxonomy.
  • lab_id and sample_id connect laboratory records to field efforts and environmental metadata

2. A Few Things to Consider

Mixed Taxonomy

ASVs may be assigned to species level, or to higher taxonomic ranks. Here, we use something called mixed taxonomy: for each ASV we take the lowest rank available.

# Creating consensus taxonomic name
asv_tax <- asv_tax %>%
  mutate(
    consensus_name = coalesce(
      species, genus, family, order,
      class, phylum, kingdom))

Our consensus label represents different taxonomic ranks, which is why we refer to taxa rather than species.

Giving reads data the right “shape” and joining to taxonomy data

The ASV_table is in a wide format, with one row per ASV and one column per sample (using laboratory IDs). We will convert it into a long format, with one roe per AV-sample combination, and a column with read counts.

A long format makes it easier to filter recored, compare samples, and visualise data with tools like ggplot. It also allows sotring a lot more information per sample alongside the read data, such as environmental metadata.

We will remove combinations with zero reads to keep the table manageable. They will come back later when we build the community matrix. In the same breath, we can add the taxonomy information.

3. Inspect the Contamination and Controls

A lot of the complexity surrounding eDNA metabarcoding is due to the fact that it deals in DNA and that DNA is in fact, in the environment. This means that we can contaminate the samples with our own DNA, but also that background DNA may enter the samples after it has been collected. More importantly, samples may contaminate each other (cross-contamination). We want to avoid this as much as possible, which we do by establishing “clean” workflows, using gloves, sterilising equipment, working in clean positive-pressure environments, and so forth. However, at the end of the day, it is impossible to fully avoid contamination. Which is why we work with three types of controls.

  • Extraction controls: are extraction tubes where no sample is added, but the same process and reagents are added as if a sample was in it and DNA was being extracted. They are used to monitor contamination during the DNA extraction. We used 7, one per extraction batch.
  • Positive controls: are used at the library preparation stage, and have all the reagents plus a known source of DNA. Here we have used the DNA of a fly. It monitors whether lab equipment and kits are working correctly. We used 6, one per library.
  • Negative controls: are also used during library preparation. Like DNA extractions, they receive all the reagents, but no DNA. It monitors contamination during library preparation. Like PCs, we used six, one per library.

Let’s check the controls, first we must gather them into one place and separate them from the true samples.

4. Cleaning the data

We will apply several filters to clean the data from contamination, weak signals, and background noise.

Keeping taxonomic assignments with high confidence

First, and before we remove contaminants, we will remove detections that have low confidence (<70%). The reason of doing it in this order will be clearer in the next step.

# Exclude controls and retain confident taxonomic assignments ----
field_detections <- asv_long %>%
  anti_join(controls, by = "lab_id") %>%
  filter(confidence >= confidence_cutoff)

Combine ASVs with the same assignment

Multiple ASVs may be assigned to the same taxa. Including two or more ASVs in the same sample. So we sum those, before we apply contamination thresholds. This is why individual ASV confidence filter has to be applied before contamination thresholds.

field_counts <- field_detections %>%
  group_by(
    lab_id, consensus_name,
    across(all_of(tax_ranks))
  ) %>%
  summarise(
    reads = sum(reads),
    .groups = "drop"
  )

Contamination Thresholds

Now we prepare the contamination thresholds. For each taxa detected in an extraction or negative control, we take the largest count observed. This count will be subtracted from the corresponding field-sample count.

control_thresholds <- controls %>%
  filter(consensus_name != positive_control_taxon) %>%
  group_by(across(all_of(tax_ranks))) %>%
  summarise(
    threshold = max(reads),
    .groups = "drop")

Then, we combine the high confidence ASVs with the contamination thresholds, and use them to remove potential contamination.

# Add thresholds to high confidence and merged ASV detections
field_corrected <- field_counts %>%
  left_join(
    control_thresholds,
    by = tax_ranks) %>%
  mutate(
    threshold = replace_na(threshold, 0),
    reads = pmax(reads - threshold, 0)) %>%
  filter(reads > 0)

Final filter

Lastly, we apply one more filter. This is a general filter to remove weak-signaled background noise. We use a 0.1% relative read frequency threshold.

# Apply 0.1% relative read threshold
asv_clean <- field_corrected %>%
  group_by(lab_id) %>%
  mutate(relfreq = reads / sum(reads)) %>%
  ungroup() %>%
  filter(relfreq > relative_cutoff) %>%

  # Recalculate totals after the low-frequency detections are removed.
  group_by(lab_id) %>%
  mutate(
    total_reads = sum(reads),
    relfreq = reads / total_reads
  ) %>%
  ungroup()

At this point, our eDNA Metabarcoding dataset is ready for analysis. We are only missing the environmental metadata.

6. Community Matrix - back to wide

We took wide datasets, and made them long. However, many of the tools for analysis we will use later on, want wide datasets. This is typical of multivariate analysis methods like NMDS, or RDA. They take a community matrix as the basic input, and then separate matrices for other inputs like environmental metadata.

However, while our original ASV_table was ASV (rows) by samples (columns), community matrices are samples (rows) by taxa (columns).

This will bring back the zeroes we discarded earlier too. Later, we will save this as an output for the next session.

comm <- asv_cc %>%
  select(sample_id, consensus_name, reads) %>%
  pivot_wider(
    names_from = consensus_name,
    values_from = reads,
    values_fill = 0,
    values_fn = sum
  ) %>%
  column_to_rownames("sample_id") %>%
  as.matrix()

7. Explore read-based rarefaction

Rarefaction curves lets us evaluate whether the “sampling effort”, in our case, reading depth, is enough to capture the diversity within a sample. It is strikingly simple, but very useful. For each sample, we will sample one read at a time (or groups of 10s or 100s of reads), and we will look at how many taxa we recover. We will do that repeatedly until we run out of reads to take from the samples, and each time, we look at the taxa we recover. If we find new taxa, we add them to the previous figure of taxa. If we have enough “effort”, should run out of new taxa before we run out of reads. If we plot this, we should see a line that plateaus.

rarecurve_df <- rarecurve(
  comm,
  step = 100,
  label = FALSE,
  tidy = TRUE
) %>%
  as_tibble() %>%
  mutate(sample_id = as.character(Site)) %>%

  # Attach habitat information to each sample's curve.
  left_join(
    metadata_cc %>% select(sample_id, treatment),
    by = "sample_id",

Some of the lines to the left of 3,000 are not yet flat. The issue with these samples is that we have “missed” taxa in them, and thus they may skew our metrics of richness.

At this point we have a choice. Increasing read depth typically leads to increased taxonomic richness. To address this, we can rarefy our data, this means that we only keep as many reads as there are in our sample with the fewest reads. The problem with doing this, is that if your lowest is too low, you might lose valuable information from your other samples. Alternatively, if most samples have flat curves, and only a few samples do not, it may be preferable to remove those samples. Here, we have kept samples with at least 3,000 reads and then worked with relative read abundance instead of rarefied reads. Both arrive at a similar destination.

8. Species Accummulation Curves

In a similar way to how we have assesed whether read depth was sufficient to capture sample-level richness. We can assess whether the sample size was enough to capture habitat-level richness. These are called species accummulation curves, and use the same process as described above, only at sample-level, instead of read-level.

Here, we will use a package called iNEXT, which provides a more robust workflow by using permutation to provide confidence intervals. We must provide two things:

  1. The total number of samples per habitat.
  2. The number of those samples in which each taxonomic label was detected.

This format of data is called incidence-frequency which we can prepare from the presence-absence community matrix.

# Count the samples in which each taxon was detected, by habitat ----
incidence <- comm_pa %>%
  as_tibble() %>%
  mutate(treatment = metadata_keep$treatment) %>%
  group_by(treatment) %>%
  summarise(across(everything(), sum), .groups = "drop") %>%
  pivot_longer(-treatment, names_to = "taxon", values_to = "frequency") %>%
  filter(frequency > 0)

# Put the total sample count first in each habitat's iNEXT vector ----
incidence <- bind_rows(count(metadata_keep, treatment, name = "frequency"),
                       incidence)
inext_input <- split(incidence$frequency, incidence$treatment, drop = TRUE)
