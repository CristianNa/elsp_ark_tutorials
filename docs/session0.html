Session 0: You have been sent eDNA data. What do you do?

We show you in this tutorial

In this session, we will go through the checks and steps you must do to have a working and interpretable dataset.

We will achieve this by:

  1. Join read data to their assigned taxonomic units.
  2. Check laboratory controls for potential sources of contamination.
  3. Apply filters to remove contamination, and other weak-signal data.
  4. Prepare community matrices alongside the associated metadata.
  5. Explore sequencing depth and species accumulation over effort.

Here, we will use the example of an 18S dataset targeting metazoan invertebrates in a Scottish landscape and across four habitat types, heath, regen, commercial woodland, and mature woodland.

2. Read the four input tables

Now we load our data. This will be acombination of data you hold, such as environmental metadata, and data that is sent to you. The latter, are typically in a “text” format, and split in several ways. Here, we have an ASV_table, which has ASV IDs as rows, and the lab IDs of samples as columns. The values within the cells correspond to the number of reads for a given ASV in a given sample. We also have the ASV_tax. This one has the taxonomic assignment for each ASV. We then have a conversion table from lab ID to field ID for our samples. Lastly, the metadata. The four are connected through identifiers, and can be merged as follows:

  • asv_id connects read counts to taxonomy.
  • lab_id connects sequencing columns to laboratory records and metadata.
  • sample_id identifies the biological samples used in the analyses.

3. A Few Things to Consider

Mixed Taxonomy

An ASV may have a species assignment, a genus assignment, or only a higher-rank assignment. Here, we use something called mixed taxonomy. Rather than dropping higher level assignments, we treat them as if they represented at least one other taxa.

asv_tax <- asv_tax %>%
  mutate(
    consensus_name = coalesce(
      species, genus, family, order,
      class, phylum, kingdom
    )
  )

This is why we typically refer to taxa, rather than species.

Fixing Mistakes

Mistakes are unavoidable. Here, the positive and negative control and a sample got mixed up in the 96-well plate. This was obvious when exploring the controls (below):

  • PC03 becomes AP845.
  • NC03 becomes PC03.

To do this, we take the lab names from the asv_table, and rename them to the right ID.

sample_key <- tibble(

        lab_id == "PC03" ~ "AP845",
        lab_id == "NC03" ~ "PC03",

Now that we have the right IDs, we can use the same table, to separate a few things. Currently we have two types of samples. True samples, and controls. Controls include extraction controls, positive controls, and negative controls. - Extraction controls are tubes where no sample is added, but where the same process and ragents are added as if DNA was being extracted. They are used to monitor contamination during the DNA extraction. - Positive controls are used at the library preparation stage, and have all the reagents plus a known source of DNA. Here we have used the DNA of a fly. It monitors whether lab stages are working correctly. - Negative controls are also used during library preparation. Like DNA extractions, they receive all the reagents, but no DNA. It monitors contamination during library preparation.

sample_key <- sample_key %>%

    by = "lab_id"

      str_detect(

We will get rid of rows where ASVs have zero reads in a given sample, to keep the table to a reasonable size. They will come back later.

Contamination Thresholds

For each taxa detected in the controls, we take the largest count observed. This count will be subtracted from the corresponding field-sample count.

control_thresholds <- controls %>%
  filter(consensus_name != positive_control_taxon) %>%
  group_by(across(all_of(tax_ranks))) %>%
  summarise(
    threshold = max(reads),
    .groups = "drop"

6. Cleaning the data

Keeping taxonomic assignments with high confidence

Before we remove contaminants, we will remove detections that have low confidence (<70%).

field_detections <- asv_long %>%
  filter(
    sample_type == "Field sample",
    confidence >= confidence_cutoff
  )

Combine ASVs with the same assignment

Multiple ASVs may be assigned to the same taxa. Including two ASVs in the same sample. So we combine those, before we apply contamination thresholds.

field_counts <- field_detections %>%
  group_by(
    lab_id, consensus_name,
    across(all_of(tax_ranks))
  ) %>%
  summarise(
    reads = sum(reads),
    .groups = "drop"
  )

Contamination thresholds

We combine the field_counts which has each sample’s and taxa read data with the contamination threshold dataset we created earlier. We then do the difference, and detections that drop to zero, we remove.

field_corrected <- field_counts %>%
  left_join(
    control_thresholds,
    by = tax_ranks) %>%
  mutate(
    threshold = replace_na(threshold, 0),

    # Clamp corrected counts at zero before removing non-detections.
    reads = pmax(reads - threshold, 0)
  ) %>%
  filter(reads > 0)

Final filter

eDNA is a “noisy” business, and typically, thresholds of relative frequency of reads are used to prevent the data from being swamped by many low read taxa. We use a 0.1% relative read frequency threshold.

asv_clean <- field_corrected %>%
  group_by(lab_id) %>%
  mutate(relfreq = reads / sum(reads)) %>%
  ungroup() %>%
  filter(relfreq > relative_cutoff) %>%

  # Recalculate totals after the low-frequency detections are removed.
  group_by(lab_id) %>%
  mutate(
    total_reads = sum(reads),
    relfreq = reads / total_reads
  ) %>%
  ungroup()

8. Community Matrix - back to wide

We took wide datasets, and made them long. However, many of the tools for analysis we will use later on, want wide datasets. This is typical of multivariate analysis methods like NMDS, or RDA. They take a community matrix as the basic input, and then separate matrices for other inputs like environmental metadata.

While our original ASV_table was ASV (rows) by Samples (columns), community matrices are Samples (rows) by Taxa (columns).

This will bring back the zeroes we discarded earlier too. You will want to save this as an output for later analyses.

comm <- asv_cc %>%

9. Explore read-based rarefaction

Rarefaction curves lets us evaluate whether the “sampling effort”, in our case, reading depth, is enough to capture the diversity within a sample. It is strikingly simple, but equally useful. For each sample, we will sample one read at a time (or groups of 10 or 100 reads), and we will look at how many taxa we recover. We will do that repeatedly until we run out of reads to take from the samples, and each time, we look at the taxa we recover. If we find new taxa, we add them to the previous figure of taxa. If we have enough “effort”, should run out of new taxa before we run out of reads. If we plot this, we should see a line that plateaus.

Here, we have worked with relative read abundance instead of rarefied reads. Both arrive at a similar destination.

12. Species Accummulation Curves

In a similar way have assesed whether read depth was sufficient to capture sample-level richness. We can assess whether the sample size was enough to capture habitat-level richness. These are called species accummulation curve, and use the same process as described above, only at sample.

Here, we will use a package called iNEXT, which provides a more robust workflow by using permutation to provide confidence intervals. We must provide two things:

  1. The total number of retained soil samples at a given habitat.
  2. The number of those samples in which each taxonomic label was detected.

This format of data is called incidence-frequencies which we can prepare from the presence-absence community matrix.

samples_by_habitat <- split(
  metadata_keep$sample_id,
  metadata_keep$treatment,
  drop = TRUE
)

inext_input <- purrr::map(
  samples_by_habitat,
  function(sample_ids) {

    mat <- comm_pa[sample_ids, , drop = FALSE]

    # Count detections across samples for each taxonomic label.
    freq <- colSums(mat)
    freq <- freq[freq > 0]

    # iNEXT requires the sampling-unit count as the first entry.
    c(nrow(mat), freq)
  }
)

Estimate richness accumulation

iNEXT can provide a number of richness indicators, which we can select by changing the parameter q. Here we use q = 0 for taxon richness.

set.seed(123) # keeps results reproduceable between runs.

  q = 0,
